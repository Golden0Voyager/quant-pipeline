# 自选股文本全量对账设计

## 目标

让 `~/Code/quant_agents/watchlists/*.txt` 与数据库中由文本同步产生的自选股保持一致。新增股票写入数据库，文本中删除的股票软停用，重新出现时恢复跟踪。

## 同步边界

- 只管理 `source_scan = 'watchlist_sync'` 的记录。
- 手工添加或其他来源的记录不受影响。
- 不删除历史记录，使用 `status = 'inactive'` 表示已从文本清单移除。
- 活跃记录使用现有状态 `status = 'tracking'`。

## 输入规则

- 来源目录：`~/Code/quant_agents/watchlists`。
- 扫描目录一级下所有 `*.txt` 文件。
- 支持纯代码、空白分隔内容和 `#` 行内注释。
- 多文件内容取并集并去重。
- 股票代码继续使用现有 `.SH`、`.SZ`、`.BJ` 转换规则。

## 对账行为

1. 来源目录不存在：记录警告并返回，不修改数据库。
2. 来源目录存在但没有 `.txt` 文件：视为明确清空，将所有 `watchlist_sync` 记录设为 `inactive`。
3. 存在 `.txt` 但没有有效代码：同样视为明确清空。
4. 文本中存在、数据库中不存在：插入记录，状态为 `tracking`。
5. 文本中存在、数据库记录为 `inactive`：恢复为 `tracking`。
6. 文本中不存在、数据库中存在的 `watchlist_sync` 记录：改为 `inactive`。
7. 已为 `tracking` 且仍在文本中的记录保持不变。

所有数据库变更在单个事务中完成，异常时回滚，避免部分对账。

## 返回值与界面提示

同步结果包含：

- `added`：新插入数量；
- `reactivated`：从 `inactive` 恢复的数量；
- `deactivated`：因文本删除而停用的数量；
- `files`：扫描到的文本文件数。

TUI 日志和通知同时展示以上变化，避免将“无新增”误解为“没有发生同步”。

## 下游行为

- 日线全量回填和东方财富筹码目标清单只应读取活跃自选股。
- 现有 provider 的 `watchlist_get_all()` 默认行为应确认是否只返回活跃记录；若不是，同步改动需同时在调用点显式过滤 `tracking`。

## 测试

测试先行覆盖：

1. 新股票插入；
2. TXT 删除后软停用；
3. 已停用股票重新出现后恢复；
4. 多文件合并与去重；
5. 空目录和空文件清空同步来源记录；
6. 目录不存在时不修改数据库；
7. 其他 `source_scan` 来源不受影响；
8. 数据库异常时事务回滚；
9. TUI 返回值和通知文案。
